## Gotchas

**Deletion is the wrong ask for a list compiler.** These files are rebuilt from
upstream compilers on a cycle. A record deleted today is a record recompiled next
quarter from the same source — and it will have been deleted exactly as you
requested, so nothing looks wrong from either side. Permanent suppression is a
different database operation: a do-not-add entry checked at build time.

Ask which one they applied. A company that maintains a suppression list will say
so readily, because it is the better answer; one that cannot has told you to
diarise a re-check.

**A dedicated `optout@` address is a good sign and an ambiguous one.** It means
somebody built a process. It does not tell you what that process does — marketing
suppression and record deletion are different things, and an opt-out desk will
often do the first and consider the request closed. Say in the letter that you are
asking for both, so the ambiguity is theirs to resolve rather than yours to
discover later.

Former addresses matter more here than almost anywhere: a compiled consumer file
is indexed on address history, so a search limited to a current address misses the
majority of the record.

## Verification

No public listing. Ask for written confirmation that names **which suppression
list** the entry was added to and whether it is checked at every build.

Re-check by writing again after a full build cycle — roughly 90 days — if the
reply confirmed deletion but did not confirm suppression.
