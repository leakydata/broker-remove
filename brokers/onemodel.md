## Gotchas

**A truthful processor answer can be completely useless, and this is the
category where that happens most.** "We act only as a processor; please contact
the controller" is honest and unactionable, because the subject has no way to
know which former employer or vendor pushed their data into the platform. So the
first ask is not deletion — it is *name the customer*. If they cannot name it
without permission, ask them to say so explicitly and to confirm whether they
will pass the request on.

**Derived outputs are the real payload.** People-analytics products generate
scores, attrition-risk estimates and performance predictions. Those are personal
information about the subject even after the input rows are gone, and a deletion
scoped to source data leaves them intact. Name them.

**Ask about training data honestly.** Whether anything went into a model, whether
removal from a training set is possible, and what happens to a model already
trained on it. An honest description of the limits is more useful than a promise
that cannot be kept.
